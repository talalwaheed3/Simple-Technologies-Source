# Source-grounded publishing

Every case begins with evidence. Record the source/date, device, OS, symptoms, exact error, failed attempts, executed fix, settings/driver changes and verification. Mark unknowns as unknown. A suggestion in an assistant reply is not an executed repair. A screen appearing once is not proof of stable recovery.

Initial scope ends 5 April 2026 inclusive. Eight retrieved candidates are provided, all Needs Verification. The source inventory differentiates proposed paths from actual fixes. Do not publish these unchanged. Full transcripts and suitable images must be supplied to finish the historical audit.

Use `npm run import:history -- conversations.json /private/output` to triage a full ChatGPT export. The script filters each message by its timestamp, preserves source IDs privately, and writes candidate files with restricted permissions. It is a keyword-assisted inventory, not proof of complete retrieval or a solution classifier. Review all exported conversations where keyword coverage may miss a repair. Never commit/upload raw chat exports or private screenshots.

Deduplicate by root cause and verified repair, not just wording. A missing SSD caused by controller configuration differs from a physically failing SSD. Add device variants to one canonical article where the procedure is materially the same. Maintain manual related-post links and category fallback.

Write an opening that identifies the reader's symptoms immediately. Follow with a short practical answer and reproducible steps. Separate observations, likely explanations and confirmed causes. Include stop conditions and data-loss warnings where justified. Preserve commands exactly and validate against current official documentation before publication. Do not pad to a word count.

Never publish password/credential bypass, disabling security checks as a routine workaround, piracy, malware deployment or unauthorized access instructions. Reframe relevant cases as legitimate recovery or defensive diagnosis. Never include customer accounts, usernames, serials, phone numbers, private filenames, photos or activation information. Inspect each image manually.

Plain-text structured sections are intentional: they cannot execute embedded HTML or JavaScript. Optional AI drafting can later transform notes into this schema, but it must create a review draft and cannot override verification/privacy checks.
